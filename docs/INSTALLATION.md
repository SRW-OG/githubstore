# 安装功能

[项目说明](../README.md) · [架构](ARCHITECTURE.md) · [AI 使用](AI.md) · [验证记录](../DEVELOPMENT.md)

在排行榜或分类中打开软件详情，核对“选择下载包”，点击“安装所选包”。确认框列出软件、版本、安装包与实际目标目录，默认为 `C:\githubapps\<软件名>`。建议在首次安装前设置安装根；已有安装或正在安装时不能更换，目前不支持迁移。

推荐按架构匹配后依次选择绿色压缩包、便携 EXE、普通 EXE、MSI。绿色包依据明确的便携命名，或与同一发行版 EXE/MSI 归一化同名的压缩包；`Setup`/`Install` 压缩包不作为绿色包。推荐只是默认选中，可手动改选。

## 安装方式

| 包类型 | 实际行为 |
|---|---|
| ZIP | 下载校验后，在安装根的独立暂存目录安全解压，核验入口再移动到目标目录 |
| 便携 EXE | 按明确类型或便携命名规则识别，复制到目标目录，不作为安装器执行 |
| EXE 安装包 | 打开交互式向导，不猜通用静默参数；请在向导中选择确认框所示目录，可能出现 UAC |
| MSI | 使用系统 `msiexec.exe /i <安装包> /norestart` 打开向导；从包内读取公开安装目录属性和 ProductCode，能确认时预填目录，否则请手动选择 |
| 7z | 由系统自带的 `System32\tar.exe`（libarchive）解压，与 ZIP 同级防护：先校验条目名，再解压到隔离目录后复核链接与展开量。缺少该工具时在下载前明确失败，不会自动换包 |

MSI 的目录属性来自实际数据库，例如 KeePassXC 的 `INSTALL_ROOT`，读取失败时不猜属性名。EXE/MSI 都没有通用强制目录能力，也不会自动重启 Windows。

若多个主程序候选无法明确匹配软件名，会提示选择相对路径。目标内存在有效 EXE 后才写成功回执，并在“启动器”显示入口图标；不创建 Windows 桌面 `.lnk`。PE 格式核验不代表签名或安全认证。

## 下载缓存

“仅下载”和“安装”共用持久安装包缓存，先下载后安装可以复用同一文件。默认缓存根是应用数据目录下的 `cache`（通常为 `%LOCALAPPDATA%\GitHubStore\cache`，随 `GITHUBSTORE_DATA_DIR` 改变），也可在设置中保存自定义根。

实际文件位于 `<缓存根>\packages-v1\<完整来源URL的SHA256>\<文件名>`。复用时重新校验大小和摘要：有上游 SHA-256 时核对上游值；没有时核对本地 SHA-256 回执，不能只凭文件名复用。本地回执只能确认缓存字节未变化，不能证明发布者身份。

已完成安装包持续保留，没有过期或容量自动淘汰。校验失败的旧完整包会改为 `retained-invalid` 名称保留，再尝试下载；中断传输可能保留 `.part` 和断点元数据。

在“设置”的已保存缓存路径下点击“清空全部下载缓存”，确认后清除本应用 `packages-v1` 命名空间内的完整包、保留旧包、未完成文件与校验文件，没有逐包选择。下载和安装器使用缓存期间持有租约，此时清理会提示忙，请任务结束后重试。清理失败会报告跳过或残留，不把失败显示为已清零。

清空不会删除自定义根本身、根中的其他文件、已安装软件、README/AI/趋势缓存或密钥设置。没有本应用命名空间标记的历史自定义缓存目录不会自动清理。保存新根只改变后续操作使用的位置，不移动或删除旧缓存；需要清理旧根时，应先切回并保存该路径。

## 失败、取消与目录保护

已有目标目录或软件登记会阻止**首次安装**，避免覆盖。

## 升级与回退（绿色/便携安装）

本程序解包安装的绿色/便携应用支持升级：下载并校验新包、解压到隔离暂存目录、核验入口后备份旧目录、切换新版本，并以**同一个安装 ID** 更新回执；任一步失败都会恢复旧目录与旧回执。升级过程写入日志文件，启动时若发现上次中断，会先恢复旧版本再显示界面。

回退由用户在“已安装”页显式触发，只回退到保留的上一版本，保留深度为 1（再次成功升级会删除更早的备份）。

EXE/MSI 安装的应用**不**走这条升级路径：请使用软件自身的升级机制；本程序也会如实说明不支持，而不是假装可以回滚。当前不支持增量/差分更新、7z 升级、用户数据迁移或目录迁移。

下载或解压取消会停止当前任务并清理其独占安装暂存目录，完整安装包仍保留。外部安装器启动后，“取消”只停止等待，不强杀安装器，也不代表回滚；请检查其向导和 Windows 已安装应用。

安装器可能忽略所选目录、提前退出或不支持自定义目录。目标目录中没有可核验的入口时，不登记为成功。文件已提交但登记失败时保留文件并提示可能残留，请先检查目录权限和现有安装，避免反复覆盖。

## 删除（移除）已安装应用

在“已安装”页选中应用后点击“卸载”，根据安装方式处理：

- **本程序解包的 ZIP / 便携 EXE**：按安装回执确认所有权，校验受管根的直接子目录并拒绝路径穿越、重解析点等，再先撤登记、后删除该目录。中途失败会提示残留；不清理目录外的用户数据。
- **EXE / MSI 安装器安装**：从 Windows HKLM/HKCU 的 32/64 位注册卸载项中，按精确安装目录和归一化名称唯一匹配。MSI 使用系统 `msiexec /x <注册产品码> /norestart`，保留交互界面；旧回执没有 ProductCode 时也可由注册项匹配。EXE 仅使用经过校验的注册卸载命令。机器级应用会请求 UAC。

拒绝 UAC、取消或卸载失败会保留安装登记；只有确认对应 Windows 注册项已消失，才移除商店回执。卸载器提前返回而注册项仍在时，不宣称已经卸载完成。匹配缺失或不唯一时，请使用软件自己的卸载器或 Windows“已安装的应用”。

## 数据与校验

安装使用选中资产的来源快照、大小和可选 SHA-256，完成下载后独立复核。成功回执保存在数据根 `managed-apps.json`，含软件/资产身份、版本、目录、入口、计算摘要与完成时间；可读取时另存 MSI ProductCode。

ZIP 解压拒绝路径穿越、绝对路径、ADS、保留名称、尾随点/空格、大小写重复路径、符号链接和重解析点；最多 10,000 条目、2 GiB 展开量。清理安装暂存只针对本次创建的目录，不清空安装根。

实现见 [安装服务](../src/GitHubStore.App/Services/Installation/AppInstallService.cs)、[缓存服务](../src/GitHubStore.App/Services/Download/PackageCacheService.cs)、[Windows 注册卸载](../src/GitHubStore.App/Services/Inventory/RegisteredUninstallService.cs)。具体实机证据见 [开发与验证](../DEVELOPMENT.md)。
