# 可独立同步的软件目录库

客户端在“设置与关于 → 软件目录库”中配置 HTTPS JSON 直链，点击“立即同步”即可下载并应用。
也可勾选启动后台同步；程序先显示本地目录，网络失败时继续使用原目录。

## 上传到 GitHub

1. 将本目录中的 [catalog.json](catalog.json) 上传到项目仓库。
2. 在 GitHub 打开该文件，复制 **Raw** 按钮指向的下载地址。
3. 在客户端粘贴地址，点击“保存地址”或“立即同步”。

地址形如：

```text
https://raw.githubusercontent.com/<账号>/<仓库>/<分支>/catalog/catalog.json
```

请用真实账号、仓库和分支替换占位符。GitHub 的 `/blob/` 文件预览页面会返回 HTML，不是可同步的目录文件。

客户端默认使用本仓库的目录库地址：

```text
https://raw.githubusercontent.com/SRW-OG/githubstore/main/catalog/catalog.json
```

首次启动即按该地址同步，无需手动填写；在设置中清空地址并保存后不再进行远端同步。

## 文件格式与更新

文件使用与内置精选库相同的格式，`schemaVersion` 为 `1`，`entries` 为软件数组。
每项包含：

| 字段 | 内容 |
|---|---|
| `categoryId` | 内置分类 ID，例如 `system`、`dev-tools`、`network` |
| `fetchedAt` | 仓库快照的时间，ISO 8601 格式 |
| `repository` | 对应仓库的 GitHub API JSON 快照 |
| `release` | GitHub Release JSON 快照；没有发行版时为 `null` |
| `curation` | 中文用途说明、推荐来源和仓库核验范围 |
| `packagePolicy` | 可选：版本策略、分架构文件名规则、安装格式、主程序路径和升级保留路径 |

### 默认版本与下载包配置

新客户端支持在软件条目中增加下面的可选字段，旧条目不填写时继续使用通用选包规则：

```json
"packagePolicy": {
  "releaseChannel": "Stable",
  "installFormat": "PortableArchive",
  "assetRules": [
    { "architecture": "Amd64", "include": ["DBX_*_x64-portable.zip"], "exclude": ["*symbols*"] },
    { "architecture": "Arm64", "include": ["DBX_*_arm64-portable.zip"], "exclude": [] }
  ]
}
```

- `releaseChannel` 为 `Stable`（最新正式版）、`LatestPrerelease`（最新预发布版）、`Pinned`（固定标签）。固定时额外填写 `pinnedTag`，例如 `v1.2.3`；其他模式不填该字段。
- `assetRules` 按 `Amd64`、`Arm64`、`X86` 配置；`Unknown` 可作为通用架构规则。包含/排除规则仅匹配文件名，`*` 表示任意文本，`?` 表示单个字符，不支持正则表达式或下载地址。
- 显式规则没有匹配时不会自动改选安装器。操作系统、架构和辅助文件检查仍然执行，不能用规则绕过。请在更新发行版后核对规则是否仍匹配。
- `installFormat` 为 `Auto`、`PortableArchive`、`PortableExecutable` 或 `Installer`。它决定安装方式，必须与所选文件扩展名兼容。7z 解压能力在后续压缩包阶段提供。
- 可选 `executableRelativePath` 指定包内主程序，例如 `bin/Client.exe`。路径必须相对安装目录且目标通过 EXE 校验；找不到时停止，不会猜另一个程序。
- 可选 `preservePaths` 声明升级时需要保留的相对路径，例如 `["data", "settings.json"]`。只有升级功能实际使用时才生效；配置本身不会执行文件操作。

这些规则与介绍可以通过更新共享库发布。库同步先读取库内发行快照；点击刷新仓库数据时，根据版本策略向仓库请求最新正式版、预发布版或固定标签。旧客户端不会使用新字段，需要升级客户端才能生效。

可从现有条目复制结构；不要只改软件名称后保留别的仓库的发行资产或来源证据。
文件应为完整 JSON，最多 8 MiB，不能重复包含同一仓库。
客户端按已知分类、仓库身份和推荐来源格式校验整份文件，全部通过后才替换本地缓存。
目录中的介绍和快照是目录维护者提供的数据，不代表客户端再次完成了来源核验或安全认证。

维护者修改并提交此文件后，客户端下次同步就会读取新版本，不必重新发布客户端安装包；这是更新软件库的常规方式。
若只增减软件，提交 `catalog.json` 即可；新增分类或改变文件格式仍需发布新版本。
此版本每次同步下载并校验文件，尚未使用 ETag 省流量。

## 本地数据的边界

- 同步更新远端维护的软件集合；远端移除的软件会从共享目录中移除。
- 保留用户手动添加的仓库；当远端库也收录同一仓库时，自动合并为**一条记录**并以远端条目为准：仓库元数据、策展说明、分类归属与远端策略覆盖本地那份，手动标记随之取消，之后远端更新可直接生效。你手动设置的描述覆盖与多分类选择仅在首次合并时保留；后续再次同步该仓库会采用远端内容，重启不会恢复原有本地设置。
- 合并只发生在同步时。远端未收录的手动仓库照常保留，不会被自动删除。
- 保留用户明确移除软件的选择，不会在下次同步时自动加回。
- 不修改本程序的已安装登记、安装文件、设置或凭据。
- 同步后的缓存可在重启或离线时使用；清空地址只停止远端同步，不会删除已缓存的软件库。
